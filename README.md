# Audit Agent — مساعد مراجعة بـ Claude (Python)

بيفحص ميزان المراجعة، وبعد ما يتأكد إنه متوازن بيطلّع متطلبات المراجعة على **صيغة مكتبك**،
ويعمل مسودة قوائم مالية على **نموذج مكتبك**. الحسابات كلها بكود Python، وكلود بيقرر الأدوات
ويفسّر النتائج.

## الهيكل

```
audit_agent/
├── app.py                       الواجهة (Streamlit): المساعد | القوائم المالية | النماذج
├── main.py                      التشغيل من الـ terminal (ويندوز بيعرض العربي مقلوب، استخدم الواجهة)
├── agent/
│   ├── loop.py                  الـ agent loop + ذاكرة المحادثة
│   ├── prompts.py               الـ system prompt
│   ├── tools.py                 الأدوات + بوابة التوازن + الموافقة البشرية
│   ├── checks.py                فحوصات حتمية (توازن، جودة بيانات، تحليلية)
│   ├── classify.py              تصنيف الحسابات (أصل/التزام/...) وأرصدتها
│   ├── templates.py             سجل النماذج (ترفع مرة وتتخزن) + اكتشاف الأعمدة
│   ├── requirements.py          متطلبات المراجعة (سياق + مكتبة + كتابة على قالبك)
│   ├── requirements_library.json  مكتبة بداية للمتطلبات (عدّلها)
│   ├── fs.py                    القوائم المالية: تخصيص، بناء، تحقق من إجماليات نموذجك
│   ├── sample_templates.py      نماذج افتراضية للتجربة بس
│   ├── mock.py                  كلود متحاكى (من غير API key)
│   └── standards.py             بحث في نصوص المعايير اللي عندك
├── standards/                   نسخك المرخّصة من المعايير (.md / .txt)
├── templates/                   النماذج المسجّلة (بتتعمل تلقائيًا)
├── mappings/                    تخصيص الحسابات المعتمد لكل عميل (بتتعمل تلقائيًا)
├── data/make_sample.py          بيولّد ميزانين تجريبيين (واحد فيه أخطاء، وواحد متوازن)
├── outputs/                     الملفات الناتجة
└── tests/                       50 اختبار (مش محتاجة API key)
```

## التشغيل

```bash
python -m venv .venv && .venv\Scripts\activate        # لينكس/ماك: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # وحط ANTHROPIC_API_KEY من console.anthropic.com
python data/make_sample.py      # ميزانين تجريبيين
pytest                          # اختبار (من غير API)
streamlit run app.py            # لو الأمر مش معروف: python -m streamlit run app.py
```

## سير العمل

1. **ارفع الميزان** من الشريط الجانبي. بيظهر فورًا ✔ متوازن أو ✘ الفرق كام.
   لو غير متوازن، زراير المتطلبات والقوائم بتتقفل، **والأدوات نفسها بترفض في الكود** حتى لو كلود حاول.
2. **سجّل نماذجك مرة واحدة** من تبويب «النماذج»: قالب المتطلبات + نموذج القوائم المالية.
   بتتخزن في فولدر `templates/` وبتتستخدم تلقائيًا في كل جلسة بعد كده.
3. **متطلبات المراجعة**: زرار «استخراج متطلبات المراجعة» ← جدول تراجعه وتعدّله ← موافق ← ملف Excel على صيغة قالبك.
4. **القوائم المالية**: تبويب «القوائم المالية» ← راجع تخصيص كل حساب لبند في نموذجك ← «اعتماد وحفظ»
   (بيتحفظ للعميل ويتستخدم السنة الجاية) ← «جهّز مسودة القوائم» ← تنزيل.

### إزاي تجهّز نماذجك

- **ملفات Excel بصيغة xlsx** (احفظ xls بـ Save As). Word مش مدعوم دلوقتي.
- ممكن تحط في أي مكان في النموذج: `{{client}}` و`{{period}}` و`{{date}}` وهتتعبّى تلقائيًا.
- **قالب المتطلبات**: صف عناوين (م، المجال، المتطلب، المستند المطلوب، المرجع، الأهمية، الحالة...).
  الأعمدة بتتكتشف من عناوينها عربي أو إنجليزي، وتقدر تصحّح الحقل لكل عمود من تبويب النماذج.
  أي صفوف مثال تحت العناوين بتتمسح، وأي توقيعات أو هوامش تحت الجدول بتتنزّل لتحت.
- **نموذج القوائم**: كل ورقة (مركز مالي / دخل) فيها عمود للبنود وعمود للسنة الحالية وعمود للسابقة.
  **سيب الإجماليات معادلات Excel** (SUM وجمع/طرح)، والنظام بيملأ بنود الإدخال بس.
  أوراق زي التدفقات النقدية وحقوق الملكية بتتساب زي ما هي وبيتبلّغ عنها.

## إزاي الفحص بيشتغل (ومحدوديته)

- التحقق من النموذج: بعد التعبئة بحسب إجماليات نموذجك من معادلاته وأقارن (الأصول = حقوق الملكية + الالتزامات،
  وصافي الربح = المحسوب من الميزان). لو التخصيص غلط الفرق بيظهر. اتجرّب بمقارنة مستقلة مع LibreOffice.
- **لو النموذج مفيهوش صفوف إجماليات بأسماء مفهومة** (إجمالي الأصول...) الفحص بيتخطى ويتبلّغ إنه «لم يتم»،
  ومش بيتحسب نجاح.
- اكتشاف الأعمدة والتخصيص الآلي اقتراحات: **راجعها**. الاقتراح بيعتمد على كلمات في الأسماء (عربي/إنجليزي).
- أي بند لازم يتحدد له حساب أو أكتر، وأي حساب من غير بند بيمنع إعداد القوائم (عشان القوائم متطلعش ناقصة).
- `openpyxl` بيحافظ على التنسيق والمعادلات لكن ممكن يفقد رسومات بيانية أو أشكال داخل نموذجك.
- الملف الناتج مفيهوش قيم محسوبة محفوظة للمعادلات: **افتحه في Excel واضغط «Enable Editing»** وهتظهر الإجماليات.
  (ورقة «ملاحظات المسودة» جواه فيها أرقام الفحص مكتوبة.)

## مراجع المعايير

مكتبة المتطلبات (`agent/requirements_library.json`) **من تأليفي**، ومراجعها على مستوى **رقم المعيار فقط**
(مثلاً ISA 505) ومعلّمة «(مقترح)». هي نقطة بداية مش مرجع رسمي. راجعها مقابل نسخك المرخّصة،
وانسخها لـ `standards/requirements_library.json` وعدّل عليها ومكتبك هي اللي هتتستخدم.

## وضع تجريبي من غير API key

من الواجهة: اختار «تجريبي». أو من الـ terminal: `python main.py --mock "افحص ملف sample_balanced_tb.xlsx"`.
كلود متحاكى بسيناريو ثابت، والأدوات والنتايج حقيقية، لكن مفيش فهم للسياق ولا أسئلة حرة.

## أخطاء شائعة

- `AuthenticationError`: المفتاح غلط أو الرصيد في Console خلص.
- `أعمدة ناقصة` في الميزان: عدّل `COLUMN_ALIASES` في `agent/checks.py` على حسب ملفات مكتبك.
- «بند اتغيّر» في القوائم: النموذج اتعدّل بعد اعتماد التخصيص. راجع التخصيص من جديد.

## الخطوات الجاية

1. نصوص المعايير المرخّصة في `standards/` (مع ترقيم الفقرات).
2. فحوصات إضافية: مطابقة كشف بنك، عينات، تواريخ القيود.
3. قائمة التدفقات النقدية وقائمة التغير في حقوق الملكية.
4. تقييم (evals): ملفات سابقة معروف نتيجتها، وقارن مخرجات الـ agent.
5. دعم قوالب Word.

## تنبيهات

- كل المخرجات مسودات، ومحتاجة مراجعة واعتماد مراجع مختص.
- راجع التزامات السرية مع عملائك قبل رفع بياناتهم الحقيقية، وابدأ ببيانات مجهّلة.

## حزمة n8n: ميزان ← قوائم مالية + إيضاحات + متطلبات (مجلد `pack/`)

- `pack/engine.py`: بوابة التوازن (مع أسباب وتلميحات)، تعبئة نموذج القوائم والإيضاحات، تعبئة قالب المتطلبات.
- `pack/config.json`: ربط أكواد الحسابات بمجموعات النموذج (بادئات الأكواد) + بيانات الأطراف ذات العلاقة. **عدّله على دليل حسابات عميلك.**
- `pack/templates/`: نموذج القوائم وقالب المتطلبات (استبدلهم بنماذجك).
- `pack/api.py`: خدمة FastAPI (`/check` و`/build`) بيستدعيها n8n. شغّلها: `uvicorn pack.api:app --port 8000` ومعاها `API_TOKEN`.
- ميزان تجريبي: `python -m pack.sample_tb` ← `data/pack_tb_balanced.xlsx` و`pack_tb_unbalanced.xlsx`.

افتراضات: الميزان قبل الإقفال (حسابات الإيرادات والمصروفات مفتوحة)، السنة المالية تنتهي 31 ديسمبر،
`prior_balance` رصيد موقّع (مدين +/دائن −) من ميزان السنة السابقة. أي حساب غير مربوط يوقف العملية.
